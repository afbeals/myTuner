## Ranked findings

- **SUB2-01 — P2, bug/additional UX.** At 390px the section-head layout allocates a small action column: **Subscribe** wraps as `Subscrib` / `e`, and **Unsubscribe** as `Unsubscri` / `be`. Even short fixture names occupy multiple lines. Screenshot `narrow.png` makes the label damage visible; `web/src/Management.tsx:939–986` places these in side-by-side `.section-head` cards, while `web/src/styles.css:1179` allows anywhere word breaking. Stack card actions at narrow widths or reserve adequate intrinsic button width; keep the complete verb. **Accept:** Subscribe/Unsubscribe and localized or longer equivalents remain readable whole words at 390px and 200% text, with no document overflow and clear association to the channel.
- **SUB2-02 — P2, bug/additional UX.** **Mocked** guide 503 while channel catalog still loads: After School, an existing subscription, is shown **Available to add / Subscribe**. Buttons are safely disabled until guide data exists, but the membership assertion is false, and Guide order is an unexplained empty section above the error. `Management.tsx:943` derives false membership from absent guide data. Show **Subscription status unavailable**, preserve known state only when still authorized, and locate Retry within the affected guide panel. **Accept:** pending/error guide data never asserts subscribed/unsubscribed, no mutation is enabled until authoritative state is known, and retry restores membership/order without page navigation. Removing the mock and clicking Try again restored one Unsubscribe action.
- **SUB2-03 — P3, additional UX.** Other Profile has no subscriptions but still shows only Guide order instructional copy with blank space; available channels appear separately below. Add a specific empty lineup state and direct instruction to select channels, then order them. First/last Move buttons already disable correctly. **Accept:** distinguish zero subscriptions, zero eligible channels, loading and failed membership; opening the guide from an empty lineup gives a clear next action.
- **SUB2-04 — P3, additional UX.** Subscription and lineup saves refresh content without a named completion announcement. Reorder can also cause a previously focused Move button to become disabled at an edge. Provide concise “Added [channel] to [profile]” and “Moved [channel] to position N” status while retaining meaningful focus. **Accept:** a keyboard/screen-reader user can confirm position and target profile without rereading the entire page; failed saves keep the prior order and permit retry.

## Owner request and workflow contract

**SUB-01 — P2 owner proposal, not an existing modal bug.** Current navigation is a dedicated page for the globally selected profile; each channel action saves immediately. I added Other private network as admin, moved it above After School, and removed it. Removal used a browser confirmation: **Remove Other private network from this profile’s guide? Current playback will stop.** The recorded order changed; switching to Other Profile produced its independent empty guide. No app-owned subscriptions modal currently exists.

Add **Subscriptions** beside Manage on profile cards, opening a modal with a persistent profile identity and channel checklist. Preserve the current dedicated route/deep-link as an entry if useful, rather than breaking existing navigation silently. Decide **Apply/Cancel staged checklist versus immediate saves** before implementation. An Apply model must calculate added/removed channels, append new ones predictably, retain existing order, report removals and their active-playback consequence, handle partial/concurrent failures and leave unchanged subscriptions alone. Include an ordered selected section with accessible Move controls; do not let checklist sort order overwrite broadcast-guide order. **Accept:** opening for one profile cannot mutate another after global profile switching; Cancel changes nothing if staging is selected; successful save is reflected in browser/TV guide and previous/next order.

Privacy is account-relative: admin saw the other owner's private channel because admin is the explicit exception; the separate sam editor session saw **only After School**, with no other-private candidate. Header copy **Other users’ private channels stay hidden** is therefore misleading for admins; add the concise admin exception, keeping private ownership visible in admin-only candidates. Do not expose hidden candidate counts/search metadata. `src/server.ts:1470–1529` filters available channels by account visibility and profile-media access, requires profile management for mutations, appends subscriptions and stops affected playback on removal. Moving controls into Profiles must retain these authorization checks; watching permission is not managing permission.
