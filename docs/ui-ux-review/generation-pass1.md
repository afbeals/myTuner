## Ranked findings and acceptance

- **GEN-P1-01 — P2, confirmed bug: completed progress has no counts.** `/api/generation/jobs/:id` returns `get()+items` without totals (`src/server.ts:1094`); `web/src/Management.tsx:1443` expects `total/completed/failed`, unlike the aggregated list endpoint. Align the detail contract and terminal rendering. **Accept:** fresh/running/completed/failed/cancelled/reused jobs show finite counts and valid progress; completed work has no active-looking indicator and requires no reload to settle.
- **GEN-P1-02 — P2, confirmed bug: reuse preview miscounts canonical path aliases.** After successful generation the next preview said `0 reusable / 1 new`, while a repeated job reused the existing file. In this Mac fixture, configured `/var/.../generated` resolves to `/private/var/.../generated`; `generationPreflight` passes the former into `safeMediaPath`, whose containment check compares it with the canonical result (`src/generation.ts:113`, `src/catalog.ts:140`). Canonical-root inspection succeeds. **Accept:** equivalent configured/canonical roots produce the same reusable count, while escaped/symlinked outputs remain rejected. This is local evidence, not proof of an Unraid-specific cause.
- **GEN-P1-03 — P2, owner request/performance: distinguish active queue from history and stop terminal detail polling.** Timer at `Management.tsx:1190` reloads list/detail every three seconds regardless of completion; observed two completed-detail requests in 6.5 seconds. `GenerationRunner.list()` deliberately retains the newest 200 jobs (`src/generation.ts:314`). Move terminal entries into clearly labeled history, retain useful results, and refresh according to active work. **Accept:** an empty active queue is unmistakable; opening a terminal job settles without perpetual frequent polling. Decide retention/clear-history behavior before adding deletion.
- **GEN-P1-04 — P2, owner request: compact current work plus bounded result log.** Replace per-file cards with current directory/current filename and a collapsible success/failure/reused log. Detail currently fetches/maps all tasks; a legal 5,000-file × three-output job can contain 15,000 cards. **Accept:** large jobs keep DOM/response work bounded, results remain inspectable and active-file updates do not rerender an entire catalog. Collapsing text alone is insufficient if every result is still fetched each poll.
- **GEN-P1-05 — P3, owner request: clarify reuse and confirmation.** Existing checkbox and preview are functional, so avoid implementing a duplicate overwrite mechanism. Prefer a concise “Replace existing outputs” label, unchecked by default, and clear new/reused/replaced counts. Keep original media unchanged. Size/time estimates remain honestly unknown.
