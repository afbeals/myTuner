## Ranked owner-request refinements

- **SRC2-01 — P2, owner request: SRC-03/07/08, GLO-01/05/06.** Advanced import diagnostics lead the all-purpose configuration dialog, followed by multiple independent forms, before provider/refresh settings. Narrow users scroll several screens away from Close; there is no persistent footer. Apply the shared sticky-header/footer modal, concise horizontal sections that stack responsively, and a separate **Scan & refresh** workflow containing configuration, explicit start, progress and prior results. Keep diagnostics as a labeled secondary section. **Accept:** ordinary setup does not require traversing import diagnostics; Close and applicable Save stay reachable at every scroll position.
- **SRC2-02 — P2, owner request: SRC-07, GLO-08.** Existing saves are per subtitle, metadata location, provider connection and automatic refresh; subtitle Cancel is local, not a modal-wide cancel. Closing dirty forms and removing sources use native confirmations (`web/src/Management.tsx:617,780`; `web/src/ui.tsx:263`). A single footer Save is a new transaction contract, not just moving buttons. Decide atomic configuration save versus explicit staged operations; report partial failure and preserve all drafts. Keep scans/Disconnect separate deliberate actions. **Accept:** one documented save scope, visible successful/failed sections, no lost sibling drafts, and no silently started scan. Apply app confirmations for in-app discard/removal; browser tab-close remains browser-owned.
- **SRC2-03 — P2, owner request: SRC-04/05, GLO-04.** Subtitle controls mix root selection, comma-separated subdirectories, preset buttons and numeric depth, with metadata configuration visually adjacent but independently saved. Depth bounds searches inside configured caption folders (currently 0–4), protecting HDD work; it is not equivalent to finding every descendant under an arbitrary parent (`src/subtitle-catalog.ts:24,64`). Offer a plain-language parent/location choice plus bounded “Include subfolders” and an advanced depth option. Keep subtitle and NFO metadata purposes distinct. **Accept:** users understand which files will be searched and when changes take effect; bounded/cancellable reads and read-only roots remain.
- **SRC2-04 — P2, owner request: SRC-06.** “Choose mapping roots” adds paired inputs, but Add mapping row serializes back into a freeform `provider => container` textarea. Repeatable paired rows should be the primary editor (`web/src/MetadataIntegration.tsx:43,286–324`). Validate local destination readability/containment separately from provider path syntax; an upstream path may exist only on another machine. **Accept:** Add/remove/edit rows without delimiter knowledge; cached mapping preview and explicit directory check identify distinct failure causes. Real-provider save/path checks were not attempted, so no claim that every invalid mapping saves successfully.
- **SRC2-05 — P3, owner request: SRC-01/02, GLO-02/04.** The source chooser is a mount-suggestion disclosure, not a filesystem tree. It opens after Check directory/scope/explanatory controls. On this macOS fixture it showed “suggestions unavailable” alongside an empty search/list and “No matching mount suggestions”, an unnecessarily contradictory-looking empty state (`web/src/SourcePathField.tsx:150`). Place choices directly with their trigger, suppress irrelevant empty filtering when unsupported, and distinguish mounts from catalog folders. **Accept:** choices appear only after explicit opening; Linux can use safe mount metadata without Docker-daemon access; unsupported platforms keep manual entry usable. No Docker socket is required.

## Additional independent recommendations

- **SRC2-A01 — P2, additional UX:** “Configure” versus “Edit source” is hard to predict: the former contains almost all settings, while the latter contains name/root/type. Consolidate entry points under **Manage source**, with clear Source details / Captions / Metadata / Refresh sections, retaining a prominent explicit Scan action. **Accept:** users can find path and provider settings without trial opening both dialogs; source-identity reset warnings remain at the affected edits.
- **SRC2-A02 — P3, additional UX:** Hide/disable “Disconnect integration” when no integration exists. It currently appears dangerous in the fresh unconfigured source, beside a provider form with no saved connection. **Accept:** disconnected state says “Not connected” and presents Connect/Save; an actual connection retains secondary Disconnect and consequences.
- **SRC2-A03 — P3, additional UX:** Keep the readable scan summary, replace always-visible raw JSON with named counts (found/updated/missing/issues) and expandable technical details (`web/src/Management.tsx:573`). Identify the source and completion time in retained results. **Accept:** a successful scan is plainly complete; technical diagnostics stay available without dominating the workflow.
