## Ranked findings and additional recommendations

- **HELP2-01 · P2 · additional UX — bridge from instructions to an actionable destination.** TV step 5 says “In this browser, open Connect TV,” but the isolated page removes the navigation and provides no link. Other referenced docs require locating a checkout, with no browsable equivalent. Add explicit Connect TV and relevant setup-health links with authentication handoff, plus a safe packaged/readable documentation destination or concise essential steps. Do not publish secrets, local filesystem listings or an arbitrary file server. **Accept:** a signed-out phone can reach authenticated approval and return to help; operators can open complete installation/recovery guidance without guessing paths; links remain on the intended server.
- **HELP2-02 · P2 · bug/content — first-admin sequence omits the stopped-service prerequisite and server-start step.** Under Start the Unraid server, the page tells users to create the admin, then open the browser, without explicitly keeping the service stopped for bootstrap or starting it afterward. The detailed deployment runbook says bootstrap acquires the same data lock and rejects a running server. Make this a short ordered configure → keep stopped → bootstrap → clear password environment → start → check/open sequence, linking the full runbook. **Accept:** instructions state the necessary service state for each maintenance command, use the selected compose environment/image, and do not imply a bootstrap command can run beside the server. This discrepancy is confirmed by text/code review; the operational command was deliberately not run.
- **HELP2-03 · P2 · bug/accessibility — unwrapped environment-variable prose overflows enlarged narrow text.** At 320px with root text set to 24px, document width grows to 403px. In the viewed screenshot the bare `MYTUNER_ADMIN_PASSWORD` prose token escapes its content column, although adjacent code wraps. Apply safe wrapping to long technical tokens throughout help, not only code, and preserve readable command copying. **Accept:** enlarged 320/390px layouts have no horizontal document scroll or clipped token; commands retain exact underlying text and no inserted hard line-break characters.
- **HELP2-04 · P3 · owner-request refinement — organize by the reader’s task.** The 390px page is approximately 2489px tall and puts backup internals before TV installation. Add a short contents/task chooser for Server setup, Connect/install TV and Backup/recovery, with expandable optional detail where appropriate. Keep required prerequisites, read-only constraints, offline restore and session consequences visible. **Accept:** a phone user can jump directly to TV pairing without scrolling through recovery commands; heading order remains semantic and all content is keyboard/touch accessible.
- **HELP2-05 · P3 · additional UX — make device support and next-step recovery precise.** “Amazon Vega devices require a different client” can imply another myTuner client is available. State this client’s supported Android/Google TV/Android Fire OS scope and the actual unavailable-client status for Vega. Provide concise recovery paths for wrong/expired code and unreachable server, distinguishing ADB installation pairing from later myTuner approval. **Accept:** users select the right platform and code family without guessing; no instruction changes router rules or exposes debugging ports automatically.

No P0/P1 confirmed. APK delivery/download/signing policy, hosted documentation and exact device support language are product/release decisions. No new download, public signup or automatic network reconfiguration is assumed.
