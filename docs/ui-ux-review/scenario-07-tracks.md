# Scenario 07 — subtitles and alternate audio

Reviewed 2026-11-26, myTuner 0.3.0, using the existing `web-dist` and installed local Playwright/Chromium/FFmpeg. This was an actual browser walkthrough, followed by focused source inspection to explain observed behavior. Product code, tests, builds, visual baselines and Git state were not changed by this review. The only repository output is this report.

## Environment and evidence

- Isolated `e2e/server.ts --demo`, port **19310**, long synthetic episodes; signed in as the existing synthetic administrator and selected **Living Room**.
- Browser viewports **1440 × 1000** and **390 × 844**. Screenshots were inspected with `view_image`, including desktop caption controls, narrow caption overlap, narrow manual association and the failed-caption state.
- All management changes used visible UI controls. Browser DOM/media inspection, resource observations, localStorage reads and a Web Audio analyser supplied verification after those UI actions. No API writes were used to complete a UI task.
- Evidence directory: `/private/tmp/mytuner-scenario-07/`. Screenshots have matching accessibility snapshots where captured through the helper. `browser-events.json`, `server.log`, `measurements.json` and `cleanup.json` retain diagnostic evidence.
- Existing fixture: two 120-second videos, embedded English/French AAC, adjacent French VTT, matching episode English SRTs in `Subs`, generic `Subs/English.srt`, and configured-root Spanish SRT in `CustomCaptions`.
- Additional **synthetic test preconditions only**, inside this review's disposable fixture: Italian at `Subs/One/Orbit.S01E01.it.srt`, German at `Subs/One/Two/Three/Orbit.S01E01.de.srt`, plus Italian/German files under arbitrary `CustomCaptions/One/...` directories. These checked named subtitle-folder recursion, its depth bound, and explicit configured-root association. No real library or original household media was touched.

## Verified findings

### S07-01 — a nonexistent manual subtitle candidate returns a server error

**Reproduction:** My Network → Orbit Patrol → The Last Platform video details → Relative subtitle filename `Subs/DoesNotExist.srt` → **Check subtitle candidate**.

**Expected:** Explain that the subtitle file was not found in the selected root, keep the draft editable, and invite correction or a directory/mount check. A normal missing candidate should have an appropriate client-facing status rather than a generic server failure.

**Actual:** The preview request returned **HTTP 500** and the dialog displayed **“Internal server error.”** Save remained disabled. Existing discovered tracks and the draft were retained. Changing the input to `Subs/English.srt` and checking again recovered to **“Supported text; ready to associate.”** This was an ordinary real request against a nonexistent fixture path, not fault injection.

**Evidence:** `06-missing-candidate.png/.yml`, `08-candidate-recovery.png/.yml`, `browser-events.json`. The same flow rejected `../outside.srt` with HTTP 400 and **“Directory escapes source”** (`07-invalid-candidate`), so containment behavior is separate and passed.

**Explanation after observation:** `src/subtitle-catalog.ts:313` resolves the path and calls `stat`; `previewManualSubtitle` at line 345 propagates the resulting missing-path error. Translate the expected missing/unreadable candidate cases into actionable validation without exposing raw host paths to unauthorized users.

### S07-02 — player controls cover active caption text

**Desktop reproduction:** Watch After School episode 1, select French captions, choose **Largest** and **Text shadow**, and leave the player overlay visible.

**Actual:** The active **“French external fixture”** caption sits beneath the opaque control overlay and becomes difficult to read. Hiding controls restores legible white text. This is layering/positioning, not the caption font color: computed caption color was white and size was 40 px.

**Narrow reproduction:** At 390 px, select the episode-2 English caption, Largest/Text shadow, and hide controls.

**Actual:** The caption wraps into two lines; the persistent **Show controls** button covers the right side of the second line. The caption itself is present in the DOM as **“External fixture episode 2”**, but the screenshot visibly obscures part of that text.

**Expected/recommendation:** Reserve space for visible controls or place captions above them, and keep the reveal button outside the active cue's text area. Verify short and multiline captions at every supported size and both overlay states.

**Evidence:** `18-caption-largest-shadow.png`, `19-captions-shadow-no-overlay.png`, `25-narrow-track-controls.png`. All three were visually inspected. `web/src/Player.tsx:839` renders the reveal button after the caption; `web/src/styles.css:677`, `:1079` and the overlay rules use fixed caption/control positions. This finding combines the desktop and narrow versions of the same obstruction problem.

### S07-03 — failed caption delivery gives no visible retry route

**Fault precondition:** A Playwright route deliberately returned **404 only for subtitle WebVTT delivery GETs**. This represents an unavailable subtitle response; it does not prove a naturally missing source file produces that response. The route was removed before recovery.

**Reproduction:** In a healthy episode-2 player, select Off, then English subtitles while the injected response is active.

**Actual:** The player displayed **“Subtitles unavailable”**, removed the cue and retained the selected English option. Video remained healthy and advancing (`readyState=4`, not paused, observed time 62.47 s). There was no Retry button or instruction explaining how to retry. After restoring delivery, choosing Off and then the same English option recovered the cue.

**Expected/recommendation:** Keep the healthy video behavior, add a direct **Retry captions** action and an explanation of the recoverable track failure. The current generic alert gives no visible path to the successful Off/on workaround. `docs/SUBTITLES.md` says caption failures show a retry message; the actual alert supplies only the failure text.

**Evidence:** `23-injected-subtitle-404.png/.yml`, `24-subtitle-recovery.png/.yml`, `browser-events.json`. The failure screenshot was visually inspected. Focused source inspection found the generic message at `web/src/Player.tsx:552`.

## Scope and status clarity recommendations

The configured root intentionally mirrors each video's relative directory and then checks named `Subs`/`Subtitles` children. It does **not** recursively search every arbitrary child of the configured parent. Files under CustomCaptions/One were not automatically discovered, but explicit association succeeded. The help text “Selecting a parent includes its subfolders” can read more broadly than this rule. Show the mirrored-directory/named-folder rule near the separate root or link directly to its explanation.

The bounded depth is intentional and visible, not evidence of unlimited recursion or a discovery failure. A normal scan can finish with zero errors while files beyond the selected depth are excluded. The 100-folder/2,000-entry/512-candidate failure paths were not saturated in this focused walkthrough, so their partial/failure presentation remains unverified here.

Disabling recursion marked a previously discovered existing Italian file **missing** (`33-recursion-off-result`), then reenabling it marked the same file found (`35-depth3-result`). The file was never removed. This matches reconciliation of the current search scope but can suggest a storage disappearance to an operator. Prefer explaining “outside current search scope” separately from a checked path that no longer exists.

Real configuration changes requiring fresh manual association are documented in `docs/SUBTITLES.md`. The configuration dialog itself could warn that changing the search settings requires rechecking and may require manually associating generic files again. No-op saves and ordinary checks were verified to preserve bindings, so the earlier suspected unconditional persistence defect was disproven.

## Positives and remaining limits

The successful path connects setup, discovery, manual management and actual watching. Ambiguous files are not silently assigned to the wrong episode. Candidate preview is separate from saving; supported-format/size feedback is useful; path containment rejects traversal. Directory checking explains mount/path failures and avoids claiming a filename sample guarantees playback. Track preferences are profile-specific and use languages across changing per-video identifiers; unavailable preferred captions fall back without erasing the preference. Real browser AAC/HLS playback and text caption conversion worked with the installed toolchain.

This does not establish native Android/Media3 behavior, physical Bravia/Fire TV decoding, remote navigation, real household formats, assisted-technology output, image subtitle support, rich ASS styling, mid-commercial timing, long soak performance, or spinning-disk load. Both fixture episodes contain French audio, so **missing preferred audio → default fallback was not exercised**. Actual external-file removal or host permission loss was not performed; the subtitle-delivery outage above was explicitly injected. Caption 404 recovery was verified; alternate-audio network failure recovery was not injected. No new installations/downloads or emulator/real-media work occurred.
