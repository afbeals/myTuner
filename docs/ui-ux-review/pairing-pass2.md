## Ranked findings

- **PAIR2-01 · P2 · bug — review transition loses keyboard focus.** After clicking Review TV and receiving a successful review, `document.activeElement` was `body`. The dynamically inserted review is a labelled section without live status or programmatic focus. A keyboard/screen-reader user lacks a reliable continuation point before the safety-critical approval. Keep focus stable through pending, then move it deliberately to the review heading/summary or announce the step and provide an immediate next focus target. **Accept:** keyboard-only review and cancel have predictable focus; new device/code information is discoverable before approval; pending does not allow duplicate activation.
- **PAIR2-02 · P2 · additional UX — actionable expiry/unknown-code recovery.** An injected 410 expiry error remained beneath an otherwise actionable existing review with Approve TV still offered. Generic `ZZZZZZZZZZ` input produced “Invalid request.” Explain whether the code is invalid, expired, already used or belongs to another server when safely distinguishable; offer Enter new code / Check TV, reset stale review, and preserve manual fallback. **Accept:** stale approval cannot remain the primary recovery path; a new TV code can be entered without reloading; generic network failure retains safe retry.
- **PAIR2-03 · P2 · bug/content — loopback address is presented as a TV connection address.** When opened at the synthetic loopback origin, “On your TV, enter” prominently recommends `http://127.0.0.1:19024`; only subordinate copy says localhost works on the server. The same host-name limitation applies to the numeric loopback address. Detect loopback origins and present “Open this page using your server’s LAN address” before a copyable TV address. Do not guess interface/VLAN reachability. **Accept:** localhost, IPv4/IPv6 loopback, LAN hostname and reverse-proxy origin cases show appropriate guidance; authorization approval remains on the intended server.
- **PAIR2-04 · P3 · additional UX — reduce code-entry friction.** The example `ABCDE 12345` uses characters beyond the backend’s hex alphabet and the field accepts them before a generic server rejection. Use a realistic code example, visible format help only when needed, and a code-specific input mode/autocapitalization that preserves keyboard paste. **Accept:** spaces/hyphens/lowercase paste work, malformed codes get local actionable feedback, and validation does not submit approval automatically.
