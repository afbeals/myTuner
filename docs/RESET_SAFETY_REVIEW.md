# Reset safety: implementation and two independent review rounds

**Local implementation and both review rounds are complete.** Each round used three fresh independent reviewers. Every confirmed finding was fixed and retested. All destructive tests used temporary synthetic fixtures; no household database, Unraid container or original media was reset, modified or deleted.

The owner requested multiple independent agents over two rounds to protect all non-myTuner data, especially videos. Earlier general UI reviews and feature-author tests did not count as these rounds. Full current-build counts and final commands are in [verification](VERIFICATION.md).

## Delivered boundary

- Browser administrators choose selective categories or fresh start and review dependencies/counts/current retained identity. HTTP cannot execute, persist or replay a reset.
- Execution requires a stopped server, exclusive data-directory ownership, explicit active administrator/password, full offline revision, exact typed confirmation and a new verified append-only recovery backup.
- Only fixed allowlisted records in the recognized current myTuner schema may be cleared, in one foreign-key/integrity-checked transaction. The named current administrator survives; account-list order is irrelevant.
- Source directories, videos, subtitle/NFO files, generated outputs, cache files, unknown appdata/neighbor files and prior backups remain intact. There is no recursive appdata wipe, source-file deletion, live database unlink or physical-output reset option.
- Historical source/metadata/subtitle root protection survives source deletion. Persistent safety barriers prevent later output reclamation/overwrite. Quotas still count retained files and may refuse new work.
- Restore/rollback/recovery preserve the stricter union of known safety barriers. Unrecoverable damaged-state authority blocks output writes instead of guessing historical ownership.
- Offline preparation can change myTuner SQLite header/control bytes when normalizing rollback journal mode; application rows and credentials are unchanged until confirmed execution. Current-operation temporary cleanup requires verified inode ownership.

## Test scope and limits

- [x] Every category and all 255 nonempty selective combinations, dependency closure, unselected rows, schema bookkeeping and foreign-key integrity.
- [x] Custom values and actual show/media metadata reachability/order remain intact when unselected.
- [x] Explicit second-created retained admin, wrong/missing password, wrong roles, disabled/demoted accounts and confirmation failures.
- [x] Full-revision changes before execution and during backup; transactional exceptions roll back earlier deletes.
- [x] Live owner, playback/queued scan, pending restore, repeated requests and stale apply refusal.
- [x] Backup allocation/verification failure, modified verified bundle, strict manifest and real restore/login.
- [x] Videos/sidecars/unknown files/neighbor DBs/prior backups; links, aliases, misleading SQLite names and actual late replacements.
- [x] Post-reset restart/cleanup/cache/quota paths and older-backup restore preserve physical files and safety barriers.
- [x] Actual browser choices/dependencies/counts/Cancel/retained identity/forbidden roles, keyboard/axe, desktop/phone and visual regression coverage.

The reset execution path has no explicit filesystem deletion API. SQLite itself manages application journals, so excluding `rm` imports was not sufficient; both rounds explicitly challenged implicit file handling and publication boundaries. Deterministic tests are not a mathematical guarantee against every privileged external-process race or hardware fault. Keep appdata under exclusive application ownership. The Unraid helper additionally mounts only appdata, with no media mounts and no network.

Actual Windows/Linux Docker-engine acceptance, target Unraid HDD/shared resources, physical TV/Fire OS and the owner-deferred emulator work remain in [differed](differed.md). No new host software was installed. Use [the offline runbook](OPERATIONS.md#reset-application-data-offline), not the development fixture tests, for an eventual owner-directed household reset.
